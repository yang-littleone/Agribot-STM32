原PI递推保持：

```text
e_i[k] = target_i[k] - feedback_i[k]
pwm_i[k] = pwm_i[k-1] + 800*(e_i[k]-e_i[k-1]) + 500*e_i[k]
```

### 4.1 特别容易出错的采集位置

`Encoder_GetCount`是读后清零接口。只能在原100 Hz反馈计算处读取一次，随后将同一次计数复制给实验快照。严禁采集任务再调用该接口，否则反馈和记录都会被破坏。

`g_RobotQueue`是单槽覆盖队列，显示任务会取走数据，不能用作100 Hz历史记录。实验需独立FIFO或环形缓冲。

Linux当前开发工程的上行任务已切换为26字节九轴调试帧；田间版本使用24字节业务帧。头文件中的24字节宏不代表当前实际发送内容。选定版本后必须追踪发送任务和回调。本次实验模式只能有一个USART3发送者，不得混发旧帧、`printf`和新实验帧。

## 5. 固件修改要求

### 5.1 单独的实验模式

使用类似`WHEEL_RESPONSE_EXPERIMENT=1`的独立编译开关或独立Keil目标。正常工程默认不开启实验模式；实验目标输出单独命名的HEX/AXF。

实验模式下：

1. 上电默认DISARMED/IDLE，四轮目标为0，调用原驱动接口保持零驱动。
2. 禁用PS2、ROS旧下行、蓝牙等对电机指令的竞争写入。
3. 板载实验序列产生`MoveSpeed_t`：直线速度v、横向速度0、角速度0。
4. 继续通过原`ROS_Control → InverseKinematic → VelocityPIDControl → Set_PWM`执行，不用开环PWM阶跃替代速度阶跃。
5. 每周期完成一次编码器读取、一次PI递推及一次实验快照。
6. 默认使用原控制任务及名义周期；增加遥测不能阻塞控制任务。

若当前基线存在上电自测电机、非零PWM、自动启动等路径，在实验模式下阻断。零驱动应使用原`Set_PWM(0,0,0,0)`语义；不要把所有定时器比较值直接写0当成等价停止。

### 5.2 状态机与启动权限

建议固定状态编号：IDLE=0、ARMED=1、RUNNING=2、ZERO_POST=3、COMPLETE=4、FAULT=5。

```text
上电 → IDLE（零驱动）
IDLE/COMPLETE → ARM（配置合法、用户准备完成）→ ARMED
ARMED → START → RUNNING：PRE零速 → HOLD阶跃
HOLD结束 → ZERO_POST：目标回0，保留原PI自然减速
POST结束 → 保存最后样本 → COMPLETE：零驱动、PI状态清零
异常或ABORT → FAULT：目标0、零驱动、PI状态清零
FAULT → 排除异常并CLEAR_FAULT → IDLE；不能自动续跑
```

ARM不应开动电机；仅START启动指定单次序列。完成后不能自动启动下一次试验。

在进入新试次前，可清零四轮`Motor_PWM`、`Bias`、`Last_bias`，明确记录复位时点。PRE、HOLD、POST之间不得重置PI状态，否则会改变阶跃及减速响应。

### 5.3 本次新增的异常保护

- Windows以10 Hz发送有效HEARTBEAT；CRC正确、run_id匹配的心跳才更新计时。
- ARMED、RUNNING、ZERO_POST中，超过500 ms未收到心跳，应在控制任务中置FAULT并零驱动；停止延迟还受控制任务实际调度影响，不能声称硬实时保证。
- ABORT立即在下一个控制周期零驱动并清PI，记录原因。断线重连、非法命令不得自动恢复运行。
- 运行期间拒绝更改阶跃幅值、阶段时长、PI和几何配置。
- 实验新增指令速度上限0.40 m/s；仅允许预检0.05、0.10和正式0.18、0.40 m/s。原逆解±1 m/s限幅保持，实验入口另行限制。
- 数据FIFO满时控制不能等待；累计丢样数，本次数据标记为不完整，保留已收到的数据。
- 严重调度异常、计数无法编码、硬件异常的触发条件应在配置中预先明确，并记录fault_flags。不能靠分析后挑阈值删数据。

这是一套新增实验保护，不能倒写为原正式田间固件已经具备的功能。软件通信超时保护不等同于独立硬件看门狗；若已有硬件看门狗，核查并说明其实际覆盖范围。

### 5.4 正常停车与急停必须分开

- 计划POST阶段：目标从阶跃速度变为0，继续原PI，采集3 s减速过程。
- STOP：提前结束HOLD、进入记录零速阶段，标记人为提前停止，不计入完整基线试次。
- ABORT/心跳超时：直接零驱动并清状态，该段不能用于计算原PI正常停车响应。

### 5.5 快照采样顺序

建议每周期按下列顺序执行，并在metadata写明：

```text
取得控制周期时间戳
读取本周期四轮编码器增量（仅一次）
按原公式计算四轮反馈
按板载阶段选择本周期车体目标
执行原逆解与四路PI并下发PWM
形成不可变的四轮快照
非阻塞入独立队列
由低优先级串口任务发送
```

反馈是刚结束的采样区间得到的速度，PWM是本周期新计算输出。不要解释成“本条PWM已经导致了本条反馈”。每条记录需同时保存板载阶段和真实四轮目标，不能事后只按PC发命令时间拼接目标。

### 5.6 遥测不干扰控制

- 独立缓冲可从32个样本开始；实际C结构大小、heap和任务栈必须计算。
- 现有heap约15 KB，不能无依据大量扩容；检查剩余堆和栈高水位。
- `HAL_UART_Transmit_IT`缓冲必须保持到发送完成，不能反复覆盖正在发送的内存。
- UART TX完整回调推进发送；RX回调和TX回调只保留统一定义。
- ISR里不得阻塞、浮点格式化或写磁盘；使用FreeRTOS的ISR接口时核对中断优先级限制。
- 不假定DMA已经配置；没有验证的DMA不能直接启用。
- 不在控制任务调用阻塞串口发送或`printf`。
- 未收到的采样不能通过插值补成原始数据。

## 6. 新实验串口协议：固件与Python共同遵守

采用二进制协议，以确保115200波特率下尽量保留100 Hz四轮数据。这里是**新增协议设计**，不是原业务协议。

### 6.1 通用帧

```text
magic[4] = ASCII "WRS1"
version  = uint8，固定1
type     = uint8
length   = uint16，小端，表示payload字节数
payload  = length字节
crc      = uint16，小端
```

CRC采用CRC-16/CCITT-FALSE：poly=0x1021，init=0xFFFF，refin=false，refout=false，xorout=0。覆盖完整8字节头部和payload；不含CRC本身。标准测试输入ASCII`123456789`应得到0x29B1。

所有整数为小端；浮点为IEEE-754 float32。不要直接发送带编译器填充的C结构，逐字段序列化并测试长度。

帧类型：0x01遥测、0x10命令、0x11应答、0x12配置。解码器按类型限制长度：遥测84、命令16、应答14、配置不超过1024。遇到非法长度或CRC错误时重新搜索magic，保留原始字节并累计错误。

### 6.2 遥测payload：84字节，完整帧94字节

| 顺序 | 字段 | 类型/数量 | 单位与定义 |
|---:|---|---|---|
| 1 | sequence | uint32 | 每个控制周期递增，丢样也递增 |
| 2 | mcu_time_us | uint32 | 快照控制周期起点，板载时间 |
| 3 | cycle_dt_us | uint32 | 与上个控制周期起点之差 |
| 4 | run_id | uint16 | 当前试次 |
| 5 | state | uint8 | 上述状态编号 |
| 6 | stage | uint8 | PRE=0、HOLD=1、POST=2；非试验=255 |
| 7 | cmd_v、cmd_w | float32 ×2 | m/s、rad/s |
| 8 | target_A/B/C/D | float32 ×4 | 原逆解后的真实轮缘目标，m/s |
| 9 | feedback_A/B/C/D | float32 ×4 | 原控制计算的轮缘反馈，m/s |
| 10 | pwm_A/B/C/D | int16 ×4 | 传入Set_PWM的整数控制值，C/D驱动取反前 |
| 11 | encoder_A/B/C/D | int16 ×4 | 同一次读出的方向归一化计数增量 |
| 12 | battery_mv | uint16 | mV；不可获得时65535，不编造 |
| 13 | fault_flags | uint16 | 定义每一位并归档 |
| 14 | queue_drop_count | uint32 | 累计入队失败次数 |
| 15 | deadline_miss_count | uint16 | 超期累计，饱和计数；阈值记入配置 |
| 16 | control_exec_us | uint16 | 控制核心执行时长；不可可靠获得时65535 |

Python格式校验可使用：

```python
struct.Struct("<IIIHBBff4f4f4h4hHHIHH").size == 84
```

100 Hz对应9400 byte/s，115200的8N1理论有效吞吐约11520 byte/s，占用约81.6%。运行中禁止额外大包和调试文本；HELLO/GET_CONFIG在IDLE或COMPLETE读取，不能边运行边发送1024字节配置包。ACK保留少量带宽。

PWM字段是归一化的整数控制输出，不是电压、电流或直接占空比。PI限幅16700与驱动中的定时器比较基准不能混淆。

编码器边界也必须检查：C/D取负可能使极端值越出int16范围，发现越界应报告并安全停止，不能静默截断成相反方向。

### 6.3 命令payload：16字节

```text
command_sequence  uint32
opcode            uint8
reserved          uint8，固定0
run_id            uint16
step_mm_s         uint16，50/100/180/400；非运动命令为0
pre_ms            uint16
hold_ms           uint16
post_ms           uint16
```

正式单次参数为3000、5000、3000 ms，时长必须为10 ms整数倍并进行总时长校验。ARM携带全部试次参数；START必须与已锁定参数一致或仅引用锁定试次，不允许隐式改参。命令编号：HELLO=1、ARM=2、START=3、STOP=4、ABORT=5、HEARTBEAT=6、DISARM=7、GET_CONFIG=8、CLEAR_FAULT=9。

应答payload为14字节：command_sequence uint32、opcode uint8、status uint8、state uint8、stage uint8、run_id uint16、reserved uint16、fault_flags uint16。status至少区分OK、非法状态、非法参数、CRC/协议错误；明确编码。HEARTBEAT可不逐条ACK以减小带宽，其他命令需关联应答。

重复START必须幂等：只回当前状态，不能重新计时。断线重连先只读状态，不能自动重发ARM/START。

GET_CONFIG返回0x12类型的UTF-8 JSON帧，至少包括实验固件身份、基线提交、配置版本、四轮实际Kp/Ki、名义周期、几何/计数配置、限幅、心跳超时、时间分辨率及故障位定义。配置字段须来自实际控制配置；不依赖上位机写死常量作为“实际参数证明”。实现时确保JSON长度不超过1024；可用简短键，但Python归档须转换为清晰字段。

### 6.4 时间基准

优先使用不占用编码器/PWM定时器的可靠高分辨率时基。若使用DWT，必须核对实际SystemCoreClock并处理32位cycle计数回卷；不能直接将循环回卷值除频率当作连续时间。

若只能提供1 ms时基，应记录`time_resolution_us=1000`，不能声称微秒精度。无法可靠计算控制执行时长时使用规定无效值。

上位机需展开uint32微秒时钟回卷，识别MCU重启并分段；不能将重启误作正常回卷。PC保存单调时钟接收时间，但响应指标以板载时间和板载实际目标变化为准。串口传输/Windows调度延迟不作为轮速上升时间。

## 7. Windows接线与实物预检

### 7.1 作者需要准备

- B小车、正常电池、匹配的烧写器及线材。

- 稳固架空支架，四轮可以自由转动。
- 足够直线地面空间，0.4 m/s保持5 s仅HOLD就约2 m；预留起停和接管空间。
- 卷尺/卡尺、电子秤、电池电压测量手段、记录照片或视频的设备。

根据当前源码配置，接线应核对：板端PD8/TX→转换器RX，PD9/RX←转换器TX，共地。开发板排针的实际位置必须依据原理图/丝印确认，不凭MCU引脚名猜排针。

板和电机使用原供电方案。USB转TTL的电源线不得未经核实接到电机供电或与板电源重复供电。USB线在落地行驶时不得缠轮或拖拽影响试验。

### 7.2 核实轮号、方向、计数比例

1. 先在零驱动状态只读串口，确认协议、配置和状态。
2. 架空，保持未ARM。依次缓慢手动转动A/B/C/D，确认哪个反馈字段变化，贴实物标签并拍照。
3. 车辆前进方向旋转应对应归一化反馈正值；检查C/D已取反，不能再次取反。
4. 标记输出轴/车轮，缓慢转动完整若干圈，使用原控制采样计数累加，核对一圈实际计数。不要另开任务读清零定时器。
5. 实测轮径并确认每轮编码器/减速比口径，保存测量方法和照片。

计数或轮径与源码明显不一致时，暂停正式试验，说明误差对m/s换算的影响。不要静默改常量后宣称与原版本完全相同。如果需要校准版本，单独标识并记录新旧配置；不能混合汇总两版本结果。

按当前配置，10 ms采样的单计数量化约为：

```text
Δv = π×0.065 / (60000×0.01) ≈ 0.0003403 m/s
```

这是按配置推导的量级，不是实测精度。完成实际计数核对后才确定分析中的量化分辨率。

### 7.3 硬件清单必须记录

`hardware_manifest.json`至少记录：robot_id=B、日期、操作者、STM32型号/板版、电机和减速箱标签、编码器、驱动器、四轮实际位置、轮径、轮距、轴距、车辆配置/质量、附加载荷、电池型号和电压、串口模块、烧写器、架空方式、地面类型、照片路径、与A的对应关系。

未知字段用null并解释；不能把源码常量直接填写成“实测值”。MG540厂家额定参数尚未确认，不在本任务中用网上同名型号替换。

## 8. 试验方案：先预检，再20次正式试验

### 8.1 预检，不计入论文正式重复数

按顺序完成：

1. 上电、连接、断线重连均保持零驱动；GET_CONFIG成功。
2. 架空执行0.05 m/s短时预检，再视情况执行0.10 m/s；确认四轮方向与反馈、没有异常持续加速。
3. 架空低速条件下检查ABORT及停止发送心跳后的停车，记录真实停止时间与状态，确认不会自动恢复。
4. 零速记录至少30 s，检查100 Hz数据与队列负担；短暂运动预检检查采样时序。
5. 正式0.18/0.40 m/s可达性检查，避免用完全不可达速度测所谓正常阶跃响应。

0.40 m/s不能稳定达到时，不调PI来掩盖。保留预检数据，报告不可达/持续饱和原因；和作者确定范围后新增明确的修订计划，不能把另一速度伪装成0.40 m/s。

### 8.2 正式基础矩阵

每次四轮同时测量，v为正、w=0。目标由逆解获得，应核实四轮实际目标一致。

| 组别 | 试次标识 | 条件 | 目标序列 | 重复次数 |
|---|---|---|---|---:|
| 1 | B_AIR_V018_R01～R05 | 四轮架空 | 0→0.18→0 m/s | 5 |
| 2 | B_AIR_V040_R01～R05 | 四轮架空 | 0→0.40→0 m/s | 5 |
| 3 | B_GROUND_V018_R01～R05 | 水平地面、固定整车配置/载荷 | 0→0.18→0 m/s | 5 |
| 4 | B_GROUND_V040_R01～R05 | 同一地面、同一配置/载荷 | 0→0.40→0 m/s | 5 |

每次时序固定：

```text
PRE：   0～3 s，四轮目标0
HOLD：  3～8 s，四轮目标0.18或0.40 m/s
POST：  8～11 s，四轮目标0，保留原PI减速
END：   11 s结束，零驱动并清PI状态
```

按控制周期计时：PRE 300周期、HOLD 500周期、POST 300周期，合计1100条试验快照；阶段边界按实际板载记录检查。采样首尾时间跨度不必等于11.000 s，不能为凑时长增加伪样本。

每次记录四轮，共20次试验、80条轮响应序列。**统计重复单位是试次；同一次四个轮子不是四次独立试验。** 分轮汇总每种条件各n=5；如分析轮间差异，需要考虑同次关联。

每次结束后由作者重新摆车，检查线材、电压和电机温度，确认下一次准备完成。软件不自动连跑20次。正式顺序和实际顺序都记录；在同一条件内可交替两个速度，减少电池/温升随顺序变化的影响。

“落地”表示测量存在地面负载时的编码器轮速响应，不等于真实地速，也不直接证明无打滑。

### 8.3 可选扩展

完成基础矩阵后，如有必要可加0.18→0.40→0.18→0的变速响应，或已称量附加载荷条件。单独编号、预先记录时序与重复数，不能替换基础矩阵中的失败试次。

本次不强制新增田间导航、地头换行或算法消融试验。

## 11. 指标定义：测量前固定，不按结果改口径

分析以每轮目标`r_i(t)`和原始反馈`y_i(t)`为准。主指标针对PRE→HOLD正阶跃；正常减速可作为附加指标。

### 11.1 时间零点与分辨率

- `t0`：板载实际轮目标首次从0变为阶跃目标的快照时间。
- `y0`：PRE最后1 s的反馈均值。
- `r1`：HOLD内实际目标，检查一致性，不只使用计划值。
- 阶跃幅值`A=r1-y0`。若幅值异常、目标不恒定，按无效/不适用规则报告。
- 以10 ms采样得到响应，时间指标不可宣称高于真实采样能力。可线性插值估计阈值交点，但必须说明，不代表额外实测采样。

### 11.2 必须输出的指标

| 指标 | 固定计算口径 |
|---|---|
| 上升时间 | 正阶跃反馈首次跨越`y0+0.1A`至首次跨越`y0+0.9A`的时间差；未跨越为未达到，不填0 |
| 调节时间 | 自t0起首次进入误差带，且之后直到HOLD结束均保持带内、剩余观察至少1 s；存在关键缺口时不能证明连续保持 |
| 超调量 | `max(0,max_HOLD(y)-r1)/abs(A)×100%`，按原始反馈；报告量化/噪声影响，不擅自平滑峰值 |
| 末段平均误差 | HOLD最后2 s的`mean(y-r1)`，m/s；该窗未稳定则称末段均值，不称稳态性能 |
| 末段绝对误差 | 同窗`mean(abs(y-r1))` |
| 全HOLD RMSE | `sqrt(mean((y-r1)^2))`，含起始瞬态 |
| 末段RMSE | HOLD最后2 s单独计算，不与全段RMSE混称 |
| PWM饱和比例 | HOLD中`abs(pwm)>=16700`的有效采样比例，声明是控制值限幅 |
| 数据完整性 | 期望/实际帧数、缺序号、队列丢样、CRC错、周期分布、异常状态 |

调节误差带默认±5%阶跃幅值。在实际编码器量化核验后、正式测量前，固定为`max(0.05*abs(A), 2*Δv)`并写入`metric_definition.json`，报告每轮使用的绝对带宽。不得在看到结果后扩大误差带以得到更短调节时间。

若HOLD结束仍未达到调节要求，记“5 s观察窗口内未完成调节”或空值附原因，不能强行把5 s当调节时间。缺少交点、缺少足够末段样本等均用空值附标记，不用0。

可附加正常停车时间：POST开始至反馈进入预先固定零速带并持续至少1 s；只用于完整正常POST，不计算ABORT清PWM段。

### 11.3 汇总与作图

- 每个条件、速度、轮号各5次，输出逐次指标和均值±样本标准差，同时保留n有效/计划。
- 不合并四轮为n=20来夸大独立重复数。
- 给每个条件/速度绘制四轮分面目标—反馈曲线；5次重复可叠加或用均值带，统计带说明是SD还是其他量。
- 原始曲线作为主要证据，不因漂亮而删峰、移相或调平；平滑图若提供仅作辅助，标明处理方法。
- 出图单位统一m/s、s和PWM控制值；如需r/min，用已核实轮径换算并说明是输出轴/车轮转速。
- 不用编码器轮速声称车辆实际地速，不用本实验分析地面滑移率。
- 不预先承诺“误差小于某数值”“超调低于某值”；本任务验收首先是数据真实、完整、计算口径清楚。
